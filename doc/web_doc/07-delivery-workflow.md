# 07 前端交付执行流程

用户闭环是交付单位：入口 → 输入/操作 → 提交 → API → 结果 → 刷新后验证。共享 [三面需求与任务模板](07-feature-delivery-template.md)，规则加载方式见 [08](08-instruction-loading.md)。

## 影响评估

- 先识别实际源码仓库、路由、UI 消费者与现有契约，按 [00](00-index.md) 选 main 或 standalone。
- 读取 [09 信息架构](09-information-architecture.md) 和 [10 视觉基准](10-layout-and-visual-baseline.md)，核对受影响模块的任务/优先级、布局图、真实截图、代表性数据与已知问题；记录资产 ID、版本及实际打开图片后的观察，缺少资料先标记待核实。
- 页面、组件、交互和 UI 消费接口有影响时，同批实施必要前端变化；没有影响时提供消费者和兼容性证据，不制造无意义页面改动。
- 缺主前端源码、启动条件、测试环境或账号是验证阻塞，不是无前端影响。

## 设计与任务分工

- explorer 读取真实前后端目录，前后端 owner 使用同一份字段、错误、空值、分页、鉴权和异步状态契约。
- 每个任务产出一个可操作的用户流程；browser verifier 负责实际应用结果，不能只截图。
- 设计维护负责用户任务、信息层级、布局图、代表性数据、目标设计与基准审阅范围；由可用实现者/审阅者或主代理承担，记录维护人与审阅人。
- 复用目标工程的组件、token、请求、认证和 i18n；新页面或公共 token 变更先做设计检查。
- 前端无持久化场景写明原因与正确刷新行为。例如纯筛选应按既有约定重置或恢复，不能误要求数据库落库。

## 实施与验证

1. 将状态矩阵与 F-xx 覆盖写进功能计划，建立针对性的失败测试。
2. 按最小改动实现并同步 API/类型/mock/i18n/模块文档。
3. 执行适用 lint、真实 typecheck、unit 和 build，缺失命令保持 blocked。
4. 启动实际应用，验证业务结果与刷新后的状态；持久化流程核对请求和服务端回显。
5. 保留桌面 1440×900 和移动 390×844 截图，按实际断点补充中间宽度和切换后的交互，核对长文案、数值边界及代表性数据。实际打开截图，对照目标/基准列出差异、修正并重新采集复核；记录具体预期、观察、审阅范围和未解决问题。交互断言、截图和 a11y 各自证明不同内容，不能互相替代。
6. 更新 [01](01-routes.md) 至 [05](05-acceptance-checklist.md)、[09](09-information-architecture.md)/[10](10-layout-and-visual-baseline.md) 及真实模块文档的当前事实、图源、截图、元信息与证据。已审阅后再更新关联基准，失效材料先标记待更新；过程保留在计划/部署记录。
7. 按 [验收清单](05-acceptance-checklist.md) 更新各层结果和未覆盖项，不能把 fixture、静态或模板测试当作业务通过；报告明确真实项目还是测试 fixture。
