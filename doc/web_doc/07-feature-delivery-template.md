# 07 按用户流程交付模板

复制本模板到具体功能计划，保留编号文档为当前态。适用于新增页面、交互、组件或被 UI 消费的 API。仅后端范围必须开工时写明原因、消费方、前端 TODO 与未完成状态。

## 目标与 baseline

- 用户主任务、成功结果：填写。
- 交付目标：`main` / `standalone`；源码仓库、revision、路由、开发入口、部署目标分别填写。
- 范围、非目标、兼容性、影响面：填写。
- 对应模块文档与 API authority：填写实际路径。
- 需要复用的组件、请求/认证、token、i18n：填写实际路径。
- 前端设计检查：按可用工具加载一个适用前端 skill；新页面或 token 变更先做设计评审；不得用不存在的角色名假装已评审。
- 设计资料：用户任务与信息层级见 [09](09-information-architecture.md)，布局图、实际截图与基准见 [10](10-layout-and-visual-baseline.md)；填写资产 ID、代表性数据、已知问题与审阅范围，缺少资料先标记待核实。

## 三面需求覆盖表

在计划或模块文档中加入一行机器可读范围记录。它只声明覆盖范围和证据位置，不把未运行检查标成通过：

```markdown
<!-- frontend-delivery: {"scope":"full-stack","target":"main","frontendRepository":"OpenByteInc/QuantDinger-Vue","frontendRef":"<显式 ref>","evidence":"<相对报告路径或 unverified>"} -->
```

若明确无前端影响，使用 `scope: "backend-only"`，同时填写 `reason`、`consumers`、`compatibilityEvidence` 与 `frontendTODO`；无后续任务也要说明原因。UI 消费接口必须先评估影响，有影响时同步消费者，无影响时以兼容性证据说明；UI 源码变更不能声明 backend-only。公共 CI 的范围守卫只判断范围声明和文档覆盖，不替代前端构建或浏览器验收。

## 原子任务：完成一段用户流程

例如“配置并提交，看到该任务的运行状态”。不要把所有后端任务做完后才发现计划只剩一个“补前端文案”。

1. explorer 同时读真实前后端目录，确认现有实现、调用链、权限与版本。
2. 前端 owner 与后端 owner 共用 F-01 的字段、错误、空值、分页、鉴权和异步状态契约。
3. 先写有意义的失败测试，再按现有组件和服务最小实现；mock 用于稳定验证 UI 状态。
4. 同步 API 文档、消费类型/adapter、fixture、i18n 与编号模块文档。
5. browser verifier 在实际应用中检查 F-01；连接隔离测试后端，核对 payload、任务配置回显、结果与刷新后的状态。无需持久化的场景写明原因与正确刷新行为。
6. 对此流程完成非修复 lint、typecheck、单测、build、浏览器/截图/console/network/axe 检查，再决定任务状态。

前端 worker、后端 worker、browser verifier 是责任分工。按当前环境实际可用角色执行；角色不可用时明确替代，不能省略其检查职责。

## 状态与证据

| 层 | 允许状态 | 必须给出的证据 |
| --- | --- | --- |
| 后端 | 未执行 / 阻塞 / 失败 / 通过 | 针对性命令、结果、测试隔离与未覆盖边界 |
| 前端 | 未执行 / 阻塞 / 失败 / 通过 | 目标/revision；lint/typecheck/unit/build 命令与结果 |
| Mock UI | 未执行 / 阻塞 / 失败 / 通过 | 实际应用、mock 范围、五态、两视口、截图与日志 |
| 测试后端联调 | 未执行 / 阻塞 / 失败 / 通过 | 测试 URL/身份类型、真实请求、服务端回显、未 mock 的 API 范围 |
| 部署 | 未执行 / 阻塞 / 失败 / 通过 | 已验证的镜像/源码 revision 对应关系与运行版本证据 |

主产品缺源码、脚本、账号或测试后端时写阻塞及手动步骤，不将独立页结果、mock 或静态通过提升为主产品完成。

## 最终报告模板

- 结果：具体用户行为变化；更新了哪些模块文档。
- 后端：命令、结果、未覆盖项。
- 前端：目标 / revision、lint/typecheck/unit/build 结果。
- UI 证据：实际路由、E2E 命令、1440×900 与 390×844 截图、五态覆盖、console、network、axe；视觉对照附标准/基准身份、实际读图与差异处理结论。
- 联调：测试后端范围、请求与回显、仍使用 mock 的部分。
- 部署：已执行的发布/运行证据；未执行则明确未验证。
- 风险：已知缺口、阻塞、兼容与退役条件。
