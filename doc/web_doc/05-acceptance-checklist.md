# 05 前端交付验收

本文件补充项目 AGENTS.md 的前端门禁。任何用户可见改动、组件交互或被 UI 消费的接口，都要在需求表中说明对应前端交付。模板见 [07](07-feature-delivery-template.md)，命令见 [04](04-test-map.md)。

## 开工条件

- [ ] 已识别交付目标、所属源码仓库、revision、路由、开发与部署入口。
- [ ] 已读取对应编号文档和 API authority，三面需求表覆盖每个用户操作。
- [ ] 已指定前后端 owner 与 browser verifier；共享字段、错误、分页、鉴权和异步状态。
- [ ] 已核对可复用组件/token/布局/i18n；新页面或 token 变更已做设计评审。
- [ ] 仅后端范围有明确原因、消费者与兼容性证据、前端 TODO 和分阶段状态；不以范围声明抹去用户可见目标。

## 信息、样例与视觉基准

- [ ] [01 路由与入口](01-routes.md) 的页面已关联 [09 信息架构与设计决策](09-information-architecture.md) 中的主任务、信息层级、关键动作与设计理由，未知项仍明确标记。
- [ ] 页面线框图和实际截图已关联 [10 布局与视觉基准](10-layout-and-visual-baseline.md)；模板示意有明确标识，当前实现、目标设计与已审阅基准分开登记。
- [ ] 10 的资产元信息可追溯到页面/组件、状态、版本、采集时间、视口、主题、语言与数据条件，敏感数据已处理。
- [ ] [02 组件与界面基线](02-components.md) 已登记现有样例或真实页面的可运行入口与复现步骤；未强制新增依赖，样例结果与业务验收分开。
- [ ] [03 状态与 API](03-state-and-api.md) 的数据边界覆盖长文案、多语言、零值与未知值区分、极值、列表密度及适用的轮询更新，不适用项有依据。
- [ ] 03 已定义并验证焦点、Esc、提交与重复提交、失败恢复、未保存变更、滚动与刷新行为。
- [ ] 10 已为信息层级、布局/对齐/间距、排版/截断、遮挡/溢出、主题和状态外观给出可判定的视觉标准，未以“截图存在”作为标准。
- [ ] [04 测试映射](04-test-map.md) 已将数据边界、交互细则、响应式变化与视觉标准关联到实际用例或操作步骤及证据。

## 完成条件

- [ ] API、UI、契约的需求覆盖分别有实现与验证证据。
- [ ] 非修复 lint、真实 typecheck、unit、build 均有当前命令与退出码。
- [ ] 实际启动对应应用并打开目标路由；记录源码 revision，不能只记录端口。
- [ ] 用户操作闭环有业务结果断言与刷新验证；无需持久化时说明原因与预期刷新行为。
- [ ] Playwright 覆盖受影响主流程；mock 状态与测试后端联调分开报告。
- [ ] loading/empty/error/success/无权限逐项有场景和结果。
- [ ] 1440×900 与 390×844 截图；检查响应式和关键操作的可达性。
- [ ] console 无错误；network 无意外 4xx/5xx；预期错误与测试场景一一对应。
- [ ] axe 无 critical 违规；键盘、焦点、语义、对比度另有检查结果。
- [ ] 编号文档、消费类型/mock/OpenAPI/i18n 与实现同批更新。
- [ ] 视觉结论附标准/基准身份、实际读图与差异处理证据；未核实项、未执行项及残余风险明确列出，截图或样例通过未替代业务结果、API 和刷新验证。
- [ ] 最终报告分别列出后端、前端、mock UI、联调与部署状态及未覆盖项。

## 不能升级为完成的情况

| 当前证据 | 可报告结论 | 尚不能报告 |
| --- | --- | --- |
| 后端 pytest 通过 | 指定后端测试通过 | 页面已接入 / UI 完成 |
| lint/unit/build 通过但无 typecheck | 已运行项目的检查通过，类型检查阻塞 | 全部前端 DoD 通过 |
| 独立页浏览器通过 | standalone 的对应流程通过 | main 主产品通过 |
| mock 页面通过 | 指定 mock UI 场景通过 | 真实后端认证 / 作业 / 租户隔离通过 |
| 测试后端只读通过 | 指定只读路径联调通过 | 提交 / 取消通过 |
| 本地 build 与联调通过 | 指定 revision 本地已验证 | 已部署或运行镜像已更新 |
| 缺源码、脚本、凭据或测试基础设施 | blocked，给出缺失项和手动步骤 | skip 后通过 |

## 阻塞时的手动路径

1. 在所属前端仓库检出明确 revision，按已跟踪锁安装依赖，补齐缺失脚本。
2. 启动隔离测试后端与对应前端；用测试账户打开实际 route，不使用生产账户。
3. 按需求表执行用户操作，记录请求 payload、服务端回显与五态；仅在明确测试环境执行提交/取消。
4. 保存两种视口截图及清理后的 console/network/axe 证据；列出无法检查项。
5. 重新运行验证入口关联报告；待所有相关层通过后，再更新具体功能状态。

部署不是本地验证的自动后续动作。只有发布范围得到授权且运行版本得到核对时，才报告部署状态。
