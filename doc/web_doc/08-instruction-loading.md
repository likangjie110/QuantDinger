# 08 指令与技能加载核查

本文件约束“规则写在文件里”和“本次代理实际加载并执行”这两个事实，不把可见文件名当作行为证据。

## 每次用户可见变更

1. 先读取最近的 `AGENTS.md`、`doc/web_doc/00-index.md`、受影响模块文档、[09 信息架构](09-information-architecture.md)、[10 布局与视觉基准](10-layout-and-visual-baseline.md) 和 API authority。
2. 根据当前暴露的 skill metadata 选择一个适用前端 skill；若需要测试或计划，再按当前任务加载对应专项 skill。不存在的角色名、工具名和路径不视为已执行。
3. 在实现计划写三面覆盖、用户闭环、owner、浏览器 verifier、目标源码 revision 和验证目标。
4. 实现前先读文件；实现后更新对应编号文档、fixture/契约和证据位置。
5. 结束前运行实际命令，报告命令、退出码、覆盖范围、阻塞和未覆盖项。历史报告、worker 自述、静态扫描或 fixture 通过不能代替 fresh verification。

## 仅后端范围

只有在用户可见行为、页面字段、错误表现和 UI 消费契约均不改变时，才能声明 `backend-only`。开工声明必须包含：

- 原因：为什么消费者不受影响；
- 受影响消费者：页面、MCP、脚本或其他客户端；
- 兼容性证据：字段/错误/状态保持不变的测试或契约检查；
- 前端 TODO：若后续阶段仍需页面接入，写明确用户流程和目标模块。

接口虽未改路径但改变了 UI 使用的字段、枚举、错误码、空值或异步状态，仍属于前端影响，必须按 full-stack 评估。

## 角色替代

计划使用的角色必须从当前工具列表确认。专用 `worker` / `explorer` / `browser verifier` 不可用时，使用可用通用子代理或由主代理承担同一职责，并在计划和最终报告说明替代关系。不得重复调用已返回模型不可用的配置，也不得用“已分派”代替实际证据。

## 浏览器结果

浏览器工具必须打开实际应用路由；mock、测试后端和部署运行分别计数。截图、console、network、a11y 证据关联 `target`、`sourceRevision` 和 `mode`；standalone 不能冒充 main，主产品缺源码或账号时写 blocked/unverified。

视觉结论必须实际打开布局图、目标设计和运行截图，记录资产 ID、阅读方式与具体观察；文件存在、路径可解析或文字复述不算读图。读图能力不可用时记录阻塞、未覆盖范围和人工复核步骤，并按 [10](10-layout-and-visual-baseline.md) 保持“未执行/待核实”。
